# Reflections on Software Engineering – ICS 314

As I finish up ICS 314, I’ve realized that software engineering is about much more than just building web apps. While I learned a lot about coding and using modern tools, the most important lessons were about the practices and principles that help teams build reliable, maintainable software—no matter what kind of project it is.

One of the biggest lessons was about configuration management. **Configuration management** is a way to keep track of all the changes made to a project’s files and code. Before this class, I used to save different versions of my work with names like `final_version2_reallyfinal.js`. But in ICS 314, especially while working on our final project, Manoa Course Wise, I learned to use Git and GitHub. These tools let us record every change, see who made it, and go back to earlier versions if something broke. This made it much easier to work as a team, since we could all make changes at the same time and not worry about losing work or overwriting each other. I can see how configuration management would be useful for any group project, not just software-like writing a group paper or managing a shared spreadsheet.

Another key concept was **Agile project management**, and more specifically, a style called **Issue Driven Project Management (IDPM)**. Agile project management is a flexible way to organize work, where you break a big project into smaller tasks and adjust as you go, instead of planning everything out in advance. In IDPM, each task—like fixing a bug or adding a new feature—is tracked as an “issue” in a tool like GitHub. For Manoa Course Wise, we created issues for everything we needed to do, and anyone on the team could pick up a task and work on it. This made it easy to see what was left, who was working on what, and what had been finished. I realized that this approach isn’t just for coding. It would work for any group project, from planning an event to organizing a community service project, because it keeps everyone organized and accountable.

We also learned about coding standards. Coding standards are a set of rules for how code should be written. Things like how to name variables, how to format code, and how to write comments. At first, it seemed a bit strict, but as our Manoa Course Wise codebase grew, I saw how much easier it was to read, debug, and update code that followed clear standards. It’s like having a shared language, so anyone can jump in and understand what’s going on. This is something I’ll use in any future project, because it makes teamwork and maintenance so much easier.

What really stuck with me is that software engineering is about more than just writing code. It’s about people, process, and building things that last. The frameworks and languages will keep changing, but the habits of working together, staying organized, and building thoughtfully are what make great projects possible. ICS 314 gave me a solid foundation in these skills, and I’m excited to use them in whatever I build next. Whether it’s another web app, a mobile game, or something completely new.

If you’re thinking about getting into software engineering, my advice is to pay attention to the “boring” stuff like version control, project management, and coding standards. It’s what turns a cool idea into something real—and something you can actually finish.
